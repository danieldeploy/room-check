# Site-wide PT/EN translation

The portal uses two translation layers. They have different responsibilities and must not be mixed.

## 1. Static interface text

Static interface text includes headings, buttons, menu entries, placeholders, notices, validation messages and text created by JavaScript.

`src/I18n/SiteTranslations.php` is the shared catalogue for the whole website. Authenticated pages automatically load it through `SessionBar::render()`. The login page loads it directly. Legacy static strings discovered by the source audit live in `src/I18n/SiteTranslationsCoverage.php` and are merged into the same runtime catalogue.

For a new module, use the normal application shell and `SessionBar`. For new static strings, prefer declaring both languages together:

```php
require_once __DIR__ . '/src/I18n/SiteTranslations.php';
SiteTranslations::boot();

echo SiteTranslations::text('Guardar', 'Save');
```

For a formatted message:

```php
echo SiteTranslations::format(
    'Foram guardados {count} registos.',
    '{count} records were saved.',
    ['{count}' => (string) $count]
);
```

The browser translation runtime also supports audited `{value}` templates. This allows text created by JavaScript or API responses with variable values to be translated without translating the variable itself.

Existing Portuguese markup remains supported by the output translation layer, which translates visible DOM text and observes DOM changes. JSON/API payloads, script data, IDs and canonical database values are deliberately not rewritten.

User-facing JSON responses go through the shared `jsonResponse()` boundary. It localizes only known human-readable fields such as `error`, `message`, `notice` and `warning`; data, status keys and identifiers remain canonical. Exception messages may use catalogue templates and keep their runtime values unchanged. Authenticated module APIs must not emit JSON directly.

JavaScript-generated visible text is covered by the DOM observer when its Portuguese source text is present in the shared catalogue. New JavaScript modules should keep user-visible text in the site catalogue and may call `window.translateAppText(text)` when an immediate translated string is needed.

Technical markup is deliberately excluded from automatic DOM translation. `code`, `pre`, `kbd`, `samp`, scripts, styles and textareas are not rewritten. A future module can also mark any technical subtree with `data-i18n-skip`.

Quoted content is the transversal escape convention for a technical literal embedded in otherwise natural text. Text between `"…"`, `“…”`, `«…»`, `„…“`, `‘…’`, `‹…›`, constrained `'…'` pairs or backticks is preserved byte-for-byte. URLs, email addresses and `{placeholder}` / `{{placeholder}}` values are also recognized automatically. This applies to Google translation, cached translations, visible DOM text, `placeholder`, `title`, `aria-label`, alerts, confirmations and formatted API messages. Straight apostrophes inside English words such as `don't` are not treated as quotation marks. Because the convention is explicit, ordinary prose that should be translated must not be put between quotation marks merely for emphasis.

## 2. User-authored persistent content

User-authored natural-language content must be stored in both languages. Do not put it in `SiteTranslations`.

Use paired columns, for example:

- `name` / `name_en`
- `description` / `description_en`
- `instructions` / `instructions_en`

When creating user text, use:

```php
$versions = $contentTranslator->versions($text, Translator::locale());
```

When editing an existing bilingual value, always pass the saved pair:

```php
$versions = $contentTranslator->versions(
    $text,
    Translator::locale(),
    $existingPt,
    $existingEn
);
```

That order is important: an unchanged saved value is reused before calling the provider. This prevents a multi-field form from retranslating unchanged content.

Genuinely new or changed text is sent directly to Google Cloud Translation Basic. The active interface language supplies the explicit source language (`pt-PT` or `en`), and the other language is the target. There is no local dictionary, spelling gate, language detector, manual vocabulary or unknown-word list.

The browser never calls a validation-only translation endpoint. Translation occurs only as part of a real persistence operation, including an existing field's real autosave.

A failed translation must never be stored as if it were the other language. `ContentTranslator` checks only that Google returned a successful, structurally valid, non-empty response and that protected quoted text/numbers can be restored exactly once. Protection markers are unique and absent from the source; missing or duplicated markers reject the save. Cached results must retain the exact number of each protected literal. The application does not judge vocabulary, grammar or the relative length of the translation. Persisted translations are reused and are not translated again on page view.

If the configured daily quota is reached, an authenticated save is normalized into a whitelisted operation and stored in `translation_pending_jobs`. The source text is a draft only: the authoritative PT/EN columns are unchanged until the worker obtains both versions. The worker verifies the queued state fingerprint under a database lock and applies the operation atomically. A later edit for the same target increments its generation and supersedes the older draft; unrelated provider failures have bounded retries and never create a false translation.

When reading persistent bilingual content, use `Translator::localized()` at the server/data boundary. Inputs, textareas, selects, JSON view-models and normal page text must all receive the active-language value rather than relying on DOM translation of the canonical PT value.

Names of people, usernames, email addresses, phone numbers, room numbers, dates, PINs, SIP values, My2N IDs, enum values, status keys, URLs, API keys, tokens and other machine identifiers are not translated, do not use `ContentTranslator::versions()`, and do not need paired `_en` columns.

    public static function get(string $key): string
    {
        $pair = self::TEXT[$key] ?? self::TEXT['worker_failed'];
        return Translator::localized($pair[0], $pair[1]);
    }

    public static function catalog(): array
    {
        return array_column(array_values(self::TEXT), 1, 0);
    }
}
